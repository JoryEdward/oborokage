## 1. 夜之主题

### 1.1 朽道场（结构）

剑客道场的“夜之面”：樱花树林里一座破败的道场，白天荒寂，夜里樱下鬼聚集，堂内是朽英剑主（§1.2）。

**外观。** 用生成道场的同一个脚本（`tools/create_data_v2.py` 的 `dojo()`）加一道“破败”处理，生成 `structure/ruined_dojo/ruined_dojo.nbt`：
- 屋顶成片塌落（约四成，成块而不是零散地缺）；墙与纸窗残破，缺口挂蜘蛛网；
- 地板掺入去皮木与苔石；鸟居一根柱子倒下；
- 石灯笼换成灵魂灯笼；院中长满樱花叶与藤蔓；
- 院子里有几座小墓碑（每座前一支未点的蜡烛）；训练木桩换成断桩（装饰方块，不是实体）；
- 堂后有一个箱子与一块磨刀石。

**生成。**
- 生物群系同道场（樱花树林）。是否也允许相邻的草甸，见 §1.5 的决定。
- 地形适应用 `beard_box`（与道场相同，自带地基）。
- 与道场放进同一个结构集（§1.5），所以两者永远不会重叠。

**刷怪。**
- 结构范围内夜间刷樱下鬼（结构的 `spawn_overrides`）。
- 1.0 的规则不许樱下鬼在头顶有遮挡的地方自然生成（防止矿洞里刷），这里加一个例外：在朽道场的范围内，只要是夜里就允许。白天不刷，避免被做成刷怪场。

**战利品。** `chests/ruined_dojo`：
- 剑魄 3–6；
- 剑意结晶 1–3；
- 铭石（概率高于道场）；
- 燧石、灵魂灯笼；
- 5% 一把残刀（四把长刀之一）。

### 1.2 朽英剑主（第二首领）

落英剑主的亡灵形态，守在朽道场的堂内。

| 项目 | 设计 |
|---|---|
| 实体 | `oborokage:withered_lord`，`WitheredLord extends PetalLord`。亡灵特性从樱下鬼抽出为共用的 `GhostTraits`，两者共用：消隐绕背、不受摔落、不溺水、不受细雪；`undead` 等标签 |
| 数值 | 生命 260（落英剑主 200）；护甲 6、韧性 2（亡灵，比落英剑主软）；基础攻击 6 + 手中名刀；击退抗性 0.6。单次伤害上限 60、免终结，与落英剑主相同 |
| 刀 | 胧影、赤霆、霜轮、空弦之一（各 25%），外观半透明 |
| 昼夜（已定） | **夜里是完全体**：消隐冷却短，可以用「百鬼」。**白天静坐**：在堂中央打坐不动，被攻击才应战；白天不用「百鬼」（樱下鬼会被晒）。白天去打更容易，夜里更凶险，给玩家一个选择。它不怕阳光，所以不会被晒死 |
| 继承的本领 | 横扫、瞬步斩、手中刀的奥义（与落英剑主相同） |
| 新本领「百鬼」（草案名） | 只在夜里用；蓄势 30 tick，地上一圈灵魂火并显示名字；在身边唤起 3 只樱下鬼，附近每多一名玩家多 1 只，最多 5 只；24 格内樱下鬼最多 8 只，超过就不唤；冷却 600 tick。被唤起的樱下鬼不掉落、不给经验（防刷）；剑主死亡时它们一同消散 |
| 消隐 | 受伤时 25%（夜里冷却 100 tick，白天 200 tick） |
| 二阶段与人数加成 | 与落英剑主共用 §2.6 |
| 台词（草案） | 见到挑战者「……还有人记得这里。」；半血「花，早就谢了。」；倒下「终于……可以睡了。」 |
| 掉落 | 剑魄 4–8、剑意结晶 2–4；被玩家击杀时 15% 掉落手中刀的残刀（落英剑主 7.9%） |
| 外观 | 沿用樱下鬼的半透明、无腿渲染，体形 1.15 倍，另画一张贴图（苍白的羽织、残破的袴、发上落着枯花），用现有的贴图生成脚本 |
| 首领血条 | 紫色、分 10 段 |
| 其他 | 刷怪蛋、图鉴“世间”页新条目、成就（§4） |

### 1.3 满月「百鬼夜行」

满月之夜，樱花树林里出现一列由「鬼将」领头的樱下鬼队伍。

**触发。**
- 只在主世界、夜里、满月时发生。月相用 `EnvironmentAttributes.MOON_PHASE` 读取，三条版本线都有。
- 每 200 tick 检查一次站在樱花树林地表的玩家：附近 128 格内没有正在行进的队伍、这名玩家今晚还没遇到过，就以 20% 的概率在 32–48 格外的地表生成队伍。生成位置遵守樱下鬼的地表规则。
- 每名玩家每个满月夜最多一次。和平难度不发生。

**队伍。**
- 鬼将一只：樱下鬼的精英版，用持久化标记区分，不新增实体类型。体形 1.35 倍（原版 `SCALE` 属性，三条线都有），生命 90，攻击 +4，名字显示为“鬼将”，周身环绕灵魂火。
- 樱下鬼 6–9 只，附近每多一名玩家多 2 只，总数不超过 12 只。

**行为。**
- 行进时，鬼将朝 64–96 格外的一点走去，到了再换下一个点；其余成员排成一列跟在后面，彼此相隔 2–3 格。
- 行进中不主动攻击，玩家进入 8 格内或攻击任何一只时，整队应战（复用已有的“互相照应”）。
- 天亮时，没在战斗的成员化作魂火消散，不会留下一地被晒着的樱下鬼。

**奖励。**
- 鬼将：剑意结晶 2–3、剑魄 3–5。
- 其余成员按普通樱下鬼掉落。
- 成就（§4）。

**配置。** 服务端配置新增：
- `nightParade`（开关，默认开）；
- `nightParadeChance`（每次检查的概率）；
- `nightParadeMax`（队伍上限）。

**测试命令。** `/oborokage parade` 在身边立即生成一队（§2.3）。

### 1.4 刀冢地域变体

现在只有一种刀冢。改为一个结构集里的五种刀冢，按生物群系各取其一，间距仍为 36 区块：

| 变体 | 生物群系 | 外观 | 残刀倾向 |
|---|---|---|---|
| 原野刀冢（现有） | 森林、针叶林、平原、热带草原 | 现有 | 五种均等 |
| 雪原刀冢 | 雪原、积雪针叶林、雪林、积雪山坡 | 浮冰与雪层、云杉 | 霜轮 50% |
| 山岳刀冢 | 风袭丘陵、风袭森林、草甸 | 安山岩与深板岩、多一根氧化的避雷针 | 赤霆 50% |
| 樱林刀冢 | 樱花树林 | 樱花木、粉红花簇 | 胧影、胧月（胁差）合计 50% |
| 荒原刀冢（新增地域） | 沙漠、恶地 | 砂岩、枯灌木 | 空弦 50% |

“残刀倾向”指该刀冢里的残刀有一半是这一种，另一半在其余几种中均分。胁差的残刀仍然只在刀冢里出现，所有变体都可能出。

**不变的部分。** 刀冢的识别靠布局：箱子正后方是錾制石砖石碑，正前方第三格是避雷针。所有变体都保留这个布局，并且每座至少 4 支蜡烛，这样惊醒刀冢和“浮名留冢”在所有变体上照常工作。

**与道场的间隔。** 刀冢的结构集加 `exclusion_zone`：道场 2 区块内不生成刀冢。道场变密以后，两者叠在一起的可能性会变高。

### 1.5 道场密度（玩家反馈）

**原因。**
- 道场的结构集是 `random_spread`，间距 32 区块：每 512×512 格只有一个候选点，候选点恰好落在樱花树林里才生成。
- 樱花树林本身面积小。粗算一片 300×300 格的樱花林，平均只能分到约 0.34 座道场，所以大多数樱花林里一座也没有。

**改法。**
1. 道场与朽道场放进同一个结构集，权重 3 : 1。
2. 间距从 32 / 12 改为初始值 16 / 6：每 256×256 格一个候选点，候选点约为原来的 4 倍。300×300 格的樱花林平均约 1 座道场，外加约 0.3 座朽道场。
3. 两座之间至少隔 6 区块（96 格），17×17 的道场不会互相挤在一起。
4. 最终数值用跑图统计（§2.5）校准，目标定为：边长 200 格以上的樱花林，至少七成里有一座道场或朽道场。

**对已有世界的影响。** 只影响新生成的区块：已经探索过的地方不变，新去的地方按新密度生成，不会出现半截的道场。

**1.0.2 的实测（2026-10-27）。**
- 樱花林只占地表的 0.12%–0.50%，大多不到一百格见方；两百格见方以上的只占 3%。
- 间距定为 10 / 4：一百格见方以上的樱花林里有道场的，从 10% 升到 71%。
- 刀冢的排斥区没有做：它会让各处的刀冢少约四分之一，而紧挨道场的刀冢很少。
- 详见 docs/REVIEW_1.0.2.md。
- 1.1.0 把朽道场放进同一个结构集时，可以考虑加“一片樱花林最多一座”的稀疏规则，以免大樱花林里挤进太多。

**已定（§8）：**
- 只在樱花树林，不扩大到草甸；剑客的自然生成也不变。
- 先单独发 **1.0.2**，只改道场结构集的间距。1.1.0 再把朽道场加进同一个结构集：届时道场分到的候选点只剩四分之三，所以按跑图结果把间距再收紧一些（例如 14 / 5），保持道场数量不比 1.0.2 少。
- 1.0.2 的数值也用跑图统计来定，所以跑图工具的“密度统计”部分在 1.0.2 先做，1.1.0 再补上“地形贴合”。

### 2.4 联机测试

`verification/network.py` 是 0.3.1 时写的双客户端测试：一个服务器，两个客户端分别当攻击者和观察者，`--latency` 通过 `latency_proxy.py` 每个方向加 100 ms 延迟。它现在还指向 0.3.1 的 JAR，也调用了已经不存在的 `OborokageClient.cameraActive()`，跑不起来。

1.1.0 把它修好并扩充：

- **原有检查：** 连斩、架刀、奥义镜头、观察者看到对方的动作。
- **新增检查：**
  - 延迟下的连斩预演与服务端确认；
  - 居合进行中按键（1.0.1 的问题 1）在延迟下也不打断演出；
  - 两名玩家同时打落英剑主时，血量随人数提高（§2.6）；
  - B 拿走 A 打开过的刀冢里的东西，刀冢照常惊醒；
  - 观察者看到百鬼夜行的队伍。
- **运行版本：** 26.3 与 26.1.2，各跑无延迟与有延迟两次。

每次运行同时开两个客户端窗口，开始前问你。

### 2.5 跑图统计工具

新增 `run.py survey`，用正常地形（不是测试用的超平坦）和几个固定种子开服，分两部分：

1. **密度统计（不生成区块，很快）。**
   - 按结构集的放置规则，算出半径 4096 格内的所有候选点；
   - 再查每个候选点的生物群系，得出道场、朽道场、各种刀冢的实际数量；
   - 同时按 16 格网格采样生物群系，统计樱花林的总面积和每一片的大小，得出“多大的樱花林里有没有道场”。
2. **地形贴合（抽样生成）。**
   - 每种结构抽 20 处实际生成；
   - 量地板下的空气格（悬空）和房间里的实心格（嵌进山）；
   - 不合格的调整地形适应方式或模板的地基。

结果写进 1.1.0 的设计记录，§1.5 的数值据此确定。

### 2.6 首领二阶段与人数加成

落英剑主与朽英剑主共用。

**二阶段。**
- 生命第一次低于一半时（现有的“怒”），解锁手中刀的终之型。
- 蓄势 20 tick，屏幕上显示名字；冷却 300 tick；与奥义一样不能被架开。

| 刀 | 终之型（草案名） | 效果 |
|---|---|---|
| 胧影 | 残月追斩 | 连续两次瞬步斩，第二次追向目标的新位置，各 1.2 倍攻击 |
| 赤霆 | 雷域 | 身边 6 格一圈，3 秒内落雷，圈内的敌人每次 1.2 倍攻击 |
| 霜轮 | 冰狱 | 8 格冰域 5 秒：圈内敌人减速并每秒受 0.4 倍攻击，首领在冰上更快 |
| 空弦 | 弦缚 | 一根弦把目标拉到面前，随即一记 1.8 倍攻击的虚斩 |

**人数加成。**
- 进入战斗时，统计 32 格内的玩家（创造和旁观不算）：最大生命 × (1 + 0.5 × (人数 − 1))，最多 × 2.5。
- 当前血量按比例跟着变。
- 脱战 10 秒后取消加成。

## 3. 优化

### 3.1 拆分大类

不改任何玩法，只是把代码挪开，靠完整回归确认行为不变。放在所有新功能之前做，这样新代码直接写进新的结构里。

| 现在 | 拆成 |
|---|---|
| `DualCombat`（1173 行） | `DualCombat`（状态表、对外接口、每 tick 调度）、`CombatRequests`（请求校验与起手）、`CombatMoves`（招式推进、位移、命中）、`CombatEvents`（发送与广播事件、快照）、`Posture`（破势、剑意计数） |
| `DualClient`（942 行） | `DualClient`（初始化与每 tick 调度）、`ClientPrediction`（请求与预演、拒绝处理）、`ClientScenes`（场景表与服务端事件；1.0.1 的“取消规则”集中在这里）、`DualPoses`（手臂与身体姿势）、`DualHud`（HUD） |
| `UltimateFx`（932 行） | `UltimateFx`（状态表、渲染入口、地面高度），每种演出一个类：胧影、胧月、赤霆、霜轮、空弦、居合、快拔，以及新的朽英剑主「百鬼」 |
| `PetalLord`（561 行） | `PetalLord`（实体、血条、台词、带领弟子、回气）、`LordArts`（横扫、瞬步斩、奥义、终之型；朽英剑主也用） |
| `BlossomOni` 的亡灵部分 | `GhostTraits`（樱下鬼与朽英剑主共用） |

### 3.2 发布流程放进仓库

`tools/release.py`，取代这两轮在临时目录里写的脚本：

| 子命令 | 作用 |
|---|---|
| `build` | 构建三条版本线到 `dist/`（不用 `gradlew clean`，保留 `build/mc-home`） |
| `verify` | 五个版本：完整矩阵、所有专项检查，以及指定的客户端检查。用参数列表调用子进程，不经过 shell，带空格的路径不会被拆开（1.0.1 那次的错误）。结果写成 JSON，并自动更新 VERIFICATION.md 里两个标记之间的表格 |
| `package` | 打包发布目录；更新 26.2 单独包的 JAR、哈希与说明 |
| `install` | 先确认游戏没开，备份旧 JAR，把新 JAR 放进两个实例 |
| `finish` | 从上一级目录把项目文件夹与 26.2 包改名为新版本 |

另外：
- **专项检查默认包含在完整回归里。** 服务端检查加 `--only=all`：先跑完整的 250 项，再跑所有专项检查；矩阵默认用它。
- **更新文档。** VERIFICATION.md 的结构，以及我的工作备忘。

## 5. 兼容与存档

- **旧世界照常加载。** 新结构、刀冢变体和新的道场密度只出现在新生成的区块。已有的道场与刀冢不变。
- **配置。** 新增配置项都有默认值，旧的配置文件照常可用。
- **降级。** 从 1.1.0 降回 1.0.x，朽英剑主和新结构里的东西会消失。说明里会写。
- **联机。** 服务器与所有客户端都要装 1.1.0。
