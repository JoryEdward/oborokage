# 0.6.2 审查记录

## 出刀跟随视角

| 层 | 0.6.1 及以前 | 0.6.2 |
|---|---|---|
| 服务端判定 | 动作开始（按下左键）时记录水平朝向，命中 tick 沿用；除空弦外只按水平扇形判定，上下 2.2 格外的目标一律打不到 | 每一段在落刀 tick 调用 `look()` 读取当前偏航与视线；所有普通斩击都按视线的三维锥形判定，实体搜索的竖直范围与招式距离相同；单刀终式的踏步与击退、虚刃剑气使用同一视线 |
| 本地预判（顿帧、震屏） | 用场景开始时的水平朝向 | 与服务端同一锥形，用当前视线 |
| 刀光 | 用场景开始时的朝向；只有空弦随俯仰 | 每一刀在刃线行进期间跟随视角，挥完后定格；第一人称始终跟随；所有刀随俯仰倾斜 |
| 身体 | 手臂不随俯仰 | 单刀与双刀动作中双臂加上头部俯仰的 0.6 倍 |

奥义（含双月归寂的三斩）、本刀技与居合不受影响：奥义是按施展时朝向编排的镜头演出；本刀技本来就在松开时取视线；居合突进是水平冲刺。

## 其他潜在问题

| # | 现象 | 原因 | 修复 | 证据 |
|---|---|---|---|---|
| 1 | 骑乘、鞘翅滑翔、旁观模式下持刀左键无反应 | 客户端只看“手里是不是刀”就拦截左键；服务端在这些状态下拒绝连斩；`AttackEntityCallback` 又挡掉原版攻击 | `DualCombat.chainsReady / ownsAttack` 统一判断；客户端拦截与服务端回调都改用它 | 服务端检查：站立归连斩、非生物 / 滑翔 / 旁观归原版 |
| 2 | 满蓄力居合突进时转动视角会被拉回 | 每 tick 用 `teleport(x, y, z, 服务端偏航, 服务端俯仰)` 同步 | 改为位置绝对、旋转相对 0 的 `teleport(PositionMoveRotation, {Y_ROT, X_ROT})`（26.1–26.3 签名一致） | 代码审查；三条版本线编译、五版本矩阵 |
| 3 | 冷却结束立即再拔刀，新居合的姿势与刀鞘模型错乱 | 0.6.0 把满蓄力演出延长到 64 tick，长于 45 tick 冷却；姿势与模型按列表中第一个同一玩家的场景取值 | 新的拔刀包到达时移除同一玩家的旧场景 | 代码审查 |
| 4 | 单持刀的玩家不知道左键有连斩 | 操作提示只在第一次装备双刀时出现 | 第一次单持刀时提示一次 | — |

审查过但无需修改：苦力怕雷击后转换实体时雷链仍从原位置发出（位置有效）；`thunderHit` 只作用于刀斩中的目标；斩击锥形对 360° 的落花终式仍全向；近距离重叠目标（距离小于 0.39 格）始终命中。
